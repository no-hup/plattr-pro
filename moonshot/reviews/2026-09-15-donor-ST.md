# Donor inventory — staff PIN and approvals (ST)

## What a working POS does
- Price/discount editing on a line is a shop-level config flag, not a code constant — `odoo/addons/point_of_sale/models/pos_config.py:116` (`restrict_price_control`), `:178` (`manual_discount`).
- Role is derived from group membership at load, two values only: manager or cashier — `odoo/addons/point_of_sale/models/res_users.py:20`.
- Cash-drawer moves and cash-move deletes are two separate rights, both manager-or-accounting — `odoo/addons/point_of_sale/models/res_users.py:25-32`.
- Employee roles are four-way per till (admin / manager / minimal / cashier), set by lists on the config — `odoo/addons/pos_hr/models/hr_employee.py:40-50`.
- **WRONG:** employee PINs are SHA1'd and shipped to the browser, compared client-side — `odoo/addons/pos_hr/models/hr_employee.py:57-66`. A 4-digit space against a captured hash is minutes.
- Cash-count difference above a configured amount blocks close for non-managers — `odoo/addons/point_of_sale/models/pos_config.py:121,166`.
- Whether order edits are stored at all is a config flag, default off — `odoo/addons/point_of_sale/models/pos_config.py:200`; mirrored on the order at `pos_order.py:374`.
- Receipt reprints are counted on the order (`nb_print`), readonly, not copied — `odoo/addons/point_of_sale/models/pos_order.py:349`.
- Discount is authorised server-side: profile flag + role set, before any invoice state changes — `ury/ury/ury/doctype/ury_order/ury_order.py:1949-1990`; comment at `:1953-1958` states the client flag is only a UI convenience.
- **WRONG:** the ceiling is a literal `MAX_DISCOUNT_PERCENTAGE = 100` in code, and the allowed-role set is a frozenset in code — `ury_order.py:1943-1946`. Not per-restaurant, not editable.
- **WRONG:** the same role/flag check is duplicated inline with a different role set inside `make_invoice` — `ury_order.py:2008-2019` vs `:1943`. Two sources of truth for who may discount.
- Cancel is refused across branches, before anything mutates — `ury_order.py:1902-1907`.
- Cancel reason is mandatory and stored on the invoice, submitted or draft — `ury_order.py:1921,1928,1940`; it has its own report, `ury/ury/ury/report/cancelled_invoices/`.
- Delete-line, quantity, price and discount are one distinct right (`takepos.editlines`), separate from `takepos.run` which covers adding lines — `dolibarr/invoice.php:272-276`.
- Unsent lines cancel freely; only unlocked, unsaved lines (`Id == 0`) may be cancelled at all — `samba/Ticket.cs:473-480`, guard at `:487-490`.
- The ticket is locked once sent and unlocked by the cancel path itself — `samba/Ticket.cs:76-78`, `:475`.
- What the kitchen was last told is snapshotted per line on the order — `odoo/addons/pos_restaurant/models/pos_session.py:19-34`; the snapshot is the marker for "kitchen has this", and stale snapshots from an offline till are rejected by server date — `odoo/addons/point_of_sale/models/pos_order.py:396-416`.
- A cancel prints a reversing KOT to the kitchen under a `CNCL-` series listing the items pulled, and marks the original KOTs cancelled — `ury_order.py:2103-2145`.
- A paid order is never edited: cancel only applies to `draft`, and a paid one raises — `odoo/addons/point_of_sale/models/pos_order.py:1238-1246`; money comes back as a new reversing order — `:1426-1450`, and as a credit note in Dolibarr — `dolibarr/invoice.php:663`.
- Failure is a hard server throw with a named reason, never a silent no-op — `ury_order.py:1953-1990`, `dolibarr/invoice.php:273-275`.

## MISSING
- Reprint is counted on the order in donors (`odoo/addons/point_of_sale/models/pos_order.py:349`); our table gives it ✓ with no PIN, no severity in R2 and no audit row. A cashier reprints a ₹2,400 bill at 23:10, settles the table on the second copy and keeps the cash — nothing in the Monday report has a number that moves.
- The cancel path in donors refuses across outlets before anything mutates (`ury/ury/ury/doctype/ury_order/ury_order.py:1902-1907`); R8 checks role only, never that the staff belongs to this `restaurantId`. One MANAGER account voids a ₹1,800 line at another outlet at 22:00 and the audit row names the right person at the wrong restaurant.
- A void prints a reversing docket to the kitchen under its own series and cancels the original KOTs (`ury_order.py:2103-2145`); we have only a screen diff, itself deferred (ST-S5, ST-Q2). The ₹450 biryani voided at 21:30 keeps cooking and is thrown away — the guest is gone, the food is paid for by the house.
- Donors make quantity and price their own rights, separate from discount (`dolibarr/invoice.php:272`, `odoo/addons/point_of_sale/models/pos_config.py:116`); our action list has neither. Dropping a sent biryani 2 → 1 at 22:40 removes ₹450 with no PIN, no reason and no row, which is a void wearing a different name.

## DIFFERENT
- PIN: donors SHA1 it to the browser and compare there (`odoo/addons/pos_hr/models/hr_employee.py:57-66`); we send it once and compare server-side with a lockout. Ours is safer — theirs is a 4-digit brute force against a hash anyone at the till can read.
- Ceiling: URY pins it in code as `MAX_DISCOUNT_PERCENTAGE = 100` with the role set frozen beside it (`ury_order.py:1943-1946`), and re-checks it a second time with a different role set (`:2008-2019`). Ours is one config key, one check. Ours is safer for the money: one source of truth, changeable without a deploy.
- Approver: Odoo makes over-limit price control a thing a cashier account simply cannot do (`odoo/addons/point_of_sale/models/pos_config.py:116`, role at `res_users.py:20`); we let the acting MANAGER clear their own over-limit with their own PIN. Theirs is safer for the money — a lone cashier at 23:00 approving themselves is a record, not a control. Ours is safer for the floor, because theirs needs a second person on site.

## OURS ALONE
- Wrong-PIN streak locks the account for a window, counters server-side (R7, ST-S3). No donor throttles PIN attempts at all — `odoo/addons/pos_hr/models/hr_employee.py:57-66` has nothing to throttle.
- Reason is mandatory and drawn from a configurable list for discounts as well as voids (R6, ST-S6). URY stores a free-text reason on cancel only (`ury_order.py:1921`); no donor asks for one on a discount.
- One generic `requires: 'pin'` challenge and resend, the same shape for later `'otp'`/`'password'`. Donors gate per action with per-action code (`dolibarr/invoice.php:272`, `ury_order.py:1949`).
