## RESOLVED — why the emulator never caught the sentinel-in-array bug (2026-09-08)

- ROOT CAUSE — the functions emulator hands the code a **`FieldValue`/`Timestamp` of `undefined`**. `firebase-tools` (13.35.1, `lib/emulator/functionsEmulatorRuntime.js`) replaces `require('firebase-admin')` with a Proxy; its `Proxied.getOriginal` returns `value.bind(target)` for any non-constructor function. `admin.firestore` in firebase-admin 12.7.0 is an arrow fn with the Firestore statics `Object.assign`-ed onto it (no `prototype`), so it gets bound and **`bind()` drops the statics**: `admin.firestore.FieldValue === undefined`, `admin.firestore.Timestamp === undefined`. Proven offline (`hasPrototype:false, afterBind_FieldValue:"undefined"`). `admin/admin.js` reads both from `admin.firestore.*`, so inside the emulator every module gets `undefined`.
- CONSEQUENCE — `utils/timestamp.js` computes `isFirebaseInitialized=false` and silently switches to its fallbacks: `serverTimestamp()` → plain map `{_seconds,_nanoseconds}`, `now()` → `Date.now()` number, `fromDate()` → map. `utils/arrayOperations.js` `safeArrayUnion/Remove` → manual read-modify-write. A plain map is a perfectly valid array element, so the emulator wrote `carts[0].statusHistory[0].timestamp` happily; prod got the real `ServerTimestampTransform` sentinel and `@google-cloud/firestore`'s serializer (client-side, `serializer.js:392`) threw. The SDK version was 7.11.6 on both sides all along — the check never ran in the emulator because no sentinel ever existed there. The e2e matrix normalizer even special-cases `_seconds` maps (`matrix/actors.mjs:68`), i.e. tests have been shaped around the fallback output.
- SCOPE (system-wide, not just timestamps): 54 `timestamp.serverTimestamp()` sites, 23 `timestamp.now()` sites and 15 `safeArrayUnion/Remove` sites have **never executed their real Firestore semantics in any emulator run**. Prod-only differences: (1) sentinels rejected inside arrays — the 5 sites fixed today; all remaining sentinel sites are top-level fields (`createdAt/updatedAt/lastUpdated/lastActivity/firstScannedAt/deletedAt/lastTokenUpdate`, plus `customer.js:32`/`customerService.js:31` `now` → top-level only) ✔; (2) `now()` fields are `Timestamp` objects in prod but epoch-ms numbers in the emulator — any comparison/sort/`toMillis()` on them is untested; (3) real `arrayUnion` de-duplicates deep-equal elements atomically, the fallback does not — `occupiedBy`/`visits`/session arrays may differ; (4) six **direct** `FieldValue.arrayUnion/arrayRemove/increment` calls (`adminApp/menu_admin.js` ×4, `menu/creation/menu_add.js`, `menu_remove.js`) throw `TypeError` in the emulator and only work in prod — a likely contributor to the long-SKIPped admin suite.
- FIX (not applied — user asked for diagnosis): in `admin/admin.js` take the two statics from the modular entry, which the stub does not touch: `const { FieldValue, Timestamp } = require('firebase-admin/firestore');` (verified: resolves to `lib/firestore/index.js`, exports both). One line; the fallbacks in `timestamp.js`/`arrayOperations.js` become dead code. Blast radius: every emulator run then stores real Timestamps/sentinels — expect fixture/golden re-records where numbers or `_seconds` maps were baked in, and the emulator would have failed checkout exactly like prod (which is the point).
