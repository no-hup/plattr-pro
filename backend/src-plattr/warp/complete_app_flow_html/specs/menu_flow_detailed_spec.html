Menu System Detailed Specification

Complete technical breakdown of menu structure, entity relationships, price calculation, and API operations

📋 Menu Structure 💰 Price Calculation 🔗 Entity Relationships ✅ Stock Management
📋 System Overview
4-Entity Model
  • Category → Groups menu items for display organization
  • MenuItem → Individual food/drink items with pricing
  • Variant → Size/type options (Small, Medium, Large)
  • Addon → Optional extras (Extra cheese, Sauce)
Variants and Addons are reusable across multiple MenuItems. They are stored separately and referenced by ID, not embedded.
📁 Database Storage Paths
restaurants/{restaurantId}/
├── categories/{categoryId}     → Category entities
├── menuItems/{menuItemId}      → Menu item entities  
├── variants/{variantId}        → Variant definitions (reusable)
└── addons/{addonId}            → Addon definitions (reusable)
🔑 Key Concepts
  • MenuItems reference variants/addons by ID, not embed them
  • Variant enrichment merges collection data with contextual name during fetch
  • Categories are ordered by order field, not alphabetically
  • Stock filtering differs between APIs (see Stock Management section)
📄 Entity Schemas
📦 MenuItem Schema
{ "menuItemId": "string", "categoryId": "string", // Foreign key to category "meta": { "name": "string", // Required "description": "string", "categoryName": "string", "image": "string" }, "priceInfo": { "basePrice": number, // Required "discount": number, // Percentage (0-100) "finalPrice": number // Calculated: basePrice * (1 - discount/100) }, "variants": [{ // Array of variant references "id": "string", // Reference to variants collection "name": "string" // Display name for this context }], "addons": ["addonId1", "addonId2"], // Array of addon IDs "nutritionalInfo": object, "allergenTags": string[], "isInStock": boolean, // Default: true "isCustomizable": boolean, // Auto-computed based on variants/addons "lastUpdated": Timestamp }
🔀 Variant Schema
{ "variantId": "string", "meta": { "name": "string", "description": "string", "categoryAssociatedWith": "string" }, "priceInfo": { "basePrice": number, "discount": number, "finalPrice": number }, "isMandatory": boolean, "respectParentDiscount": boolean, "relatedMenuItems": string[], "lastUpdated": Timestamp }
isMandatory: If true, customer MUST select this variant before adding to cart.
➕ Addon Schema
{ "id": "string", "name": "string", "priceInfo": { "basePrice": number, "discount": number, "finalPrice": number }, "respectParentDiscount": boolean, "isInStock": boolean }
respectParentDiscount: If true, inherits parent MenuItem's discount.
📁 Category Schema
{ "id": "string", "name": "string", // Required "order": number, // Required - display order "description": "string", "image": "string" }

💰 Price Calculation Flow (CRITICAL)
📊 priceInfo Object Structure
Field Type Description
basePrice number Original price before any discounts
discount number Discount percentage (0-100)
finalPrice number Pre-calculated: basePrice × (1 - discount/100)
Discount is a percentage (0-100), NOT a currency amount. finalPrice is pre-calculated and stored.
📈 Complete Price Calculation Flow
1️⃣ MenuItem.basePrice Apply MenuItem.discount → MenuItem.finalPrice
↓
2️⃣ + Variant.basePrice Apply discount (own OR parent if respectParentDiscount=true)
↓
3️⃣ + Addon.basePrice Apply discount (own OR parent if respectParentDiscount=true)
↓
4️⃣ × quantity = Cart Item Total
🎯 respectParentDiscount Behavior
How it Works
  • When respectParentDiscount = true: Variant/Addon inherits the parent MenuItem's discount %
  • When respectParentDiscount = false: Uses its own discount (or 0 if not set)
  • This calculation happens at cart calculation time, NOT stored in menu
respectParentDiscount is evaluated dynamically when adding to cart or calculating totals, NOT pre-computed in menu data.
🧮 Example Calculation
MenuItem:
  basePrice: 200, discount: 10% → finalPrice: 180

Variant (respectParentDiscount: true):
  basePrice: 50 → applies parent's 10% → adds: 45

Addon (respectParentDiscount: false):
  basePrice: 30, own discount: 0% → adds: 30

Single Item Total: 180 + 45 + 30 = 255
With quantity 2: 255 × 2 = 510
🔄 Variant & Addon Resolution
🔀 Variant Enrichment During Fetch
How Variant Resolution Works
// MenuItem stores reference: { id: "variant123", name: "Large" }
// Variant collection has: { variantId: "variant123", priceInfo: {...}, isMandatory: true }

// During fetch, these are MERGED:
const itemVariants = (item.variants || []).map(variant =>
  variants[variant.id] 
    ? { ...variants[variant.id], name: variant.name }  // Merge collection data + contextual name
    : null
).filter(Boolean);
  • Full variant data (priceInfo, isMandatory, etc.) comes from variants collection
  • Contextual name comes from MenuItem's variant reference
  • Missing variants (invalid IDs) are filtered out silently
➕ Addon Resolution
// MenuItem stores: addons: ["addon1", "addon2"]
// Direct lookup from addons collection:

const itemAddons = (item.addons || []).map(addonId => addons[addonId]).filter(Boolean);
Variants are NOT filtered by stock during fetch. Addons ARE filtered when inStock=true.
✅ Stock Management
📊 isInStock Field
Entity Has isInStock? Default
MenuItem ✅ Yes true
Addon ✅ Yes true
Variant ❌ No N/A (always available)
⚠️ API Stock Filtering Defaults (INVERTED)
API inStock Default Behavior
getRestaurantMenu false Returns ALL items regardless of stock
fetchMenu true Returns only in-stock items
These APIs have inverted default behaviors! getRestaurantMenu defaults to showing all items; fetchMenu defaults to in-stock only.
🔄 Stock Validation Timing
Menu Fetch → Cart Add → Checkout
  • Menu Fetch: Filter out unavailable items from display
  • Cart Add: Re-validate item availability before adding
  • Checkout: Final stock validation before order creation
Stock is validated at EVERY stage. Items can go out of stock between cart add and checkout.
⚙️ Auto-Computed Fields
🤖 isCustomizable
Auto-Computation Logic
const isCustomizable = (menuItemData.variants && menuItemData.variants.length > 0) || 
                       (menuItemData.addons && menuItemData.addons.length > 0);
  • Set to true if MenuItem has ANY variants OR addons
  • Recomputed on EVERY create/update operation
  • Never set manually – will be overwritten
⏰ lastUpdated
  • Set to server timestamp on every create/update
  • Uses timestamp.serverTimestamp()

▶ getRestaurantMenu PUBLIC Primary menu fetch API – default inStock=false
Request Parameters
{ "restaurantId": "string", // Required "inStock": false // Optional, default: false }
Sample Response
{ "status": "success", "message": "Restaurant menu fetched successfully", "data": { "categories": [ { "id": "cat1", "name": "Starters", "order": 1 } ], "menuItems": { "cat1": [ { "menuItemId": "item1", "meta": { "name": "Spring Rolls", ... }, "priceInfo": { "basePrice": 150, "discount": 10, "finalPrice": 135 }, "variants": [{ "id": "v1", "name": "Large", "priceInfo": {...}, ... }], "addons": [{ "id": "a1", "name": "Extra Sauce", ... }], "isInStock": true, "isCustomizable": true } ] }, "metadata": { "totalCategories": 5, "totalMenuItems": 42 } } }
⚠️ Default inStock=false returns ALL items. Pass inStock=true to filter.
▶ fetchMenu PUBLIC Secondary fetch API – default inStock=true
Request Parameters
{ "restaurantId": "string", // Required "inStock": true // Optional, default: true }
⚠️ Uses MenuValidation.validateMenuFetchInput() – stricter validation. Default inStock=true.
▶ addMenuItem PUBLIC Create a new menu item with auto-computed fields
Request Parameters
{ "restaurantId": "string", "menuItemData": { "meta": { "name": "string", "description": "string", ... }, "categoryId": "string", "priceInfo": { "basePrice": number, "discount": number }, "variants": [{ "id": "string", "name": "string" }], "addons": ["addonId1", "addonId2"], "isInStock": true // Default: true } }
Sample Response
{ "status": "success", "message": "Menu item added successfully", "data": { "menuItemId": "newItemId123", "menuItem": { ... } } }
isCustomizable is auto-computed based on variants/addons presence.
▶ updateMenuItem PUBLIC Update menu item with isCustomizable recomputation
Request Parameters
{ "restaurantId": "string", "menuItemId": "string", "updateData": { "meta": { ... }, "categoryId": "string", "priceInfo": { ... }, "variants": [...], "addons": [...], "isInStock": boolean } }
⚠️ isCustomizable is recomputed on every update based on new variants/addons.
▶ deleteMenuItem PUBLIC Delete a menu item – no cascade delete
Request Parameters
{ "restaurantId": "string", "menuItemId": "string" }
⚠️ No cascade delete – orphaned variant/addon references may remain.
▶ updateMenuItemAvailability HTTP Toggle isInStock flag – HTTP POST endpoint
Request Parameters (HTTP POST body)
{ "restaurantId": "string", "menuItemId": "string", "isAvailable": boolean // Must be explicit boolean }
⚠️ isAvailable must be an explicit boolean, not truthy/falsy values.
▶ getAllCategories INTERNAL Fetch categories ordered by order field
Function Signature
getAllCategories(restaurantRef) => Promise<Category[]> // Categories are ordered by 'order' field ascending // Throws error if any category is missing 'name' field
This is an internal function used by menu fetch operations.
