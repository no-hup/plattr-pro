📋 System Overview
Key Concepts
  • A Cart represents items a customer wants to order from a table
  • Carts are scoped to restaurantId + tableId (one cart per table)
  • Carts are stored at restaurants/{rid}/carts/{tableId}
  • Each cart contains Cart Items (menu selections with customizations)
  • Carts are linked to Sessions for customer tracking
Only ONE active cart per table at a time. Cart is cleared after successful checkout.

⚙️ Cart Item Operations
➕ Adding Items to Cart
  • Validate inputs: tableId, restaurantId, menuItemId, quantity (≥1)
  • Validate session if sessionId provided (active status check)
  • Check feature flag fallbackToSameCustomConfigurationForAddItem
  • Firestore transaction for race condition prevention
  • Validate stock: Item must be in stock (isInStock: true)
  • Process variants: Validate mandatory variants, fetch from Firestore
  • Process addons: Validate all addon IDs exist
  • Calculate item price via calculateItemPrice()
  • Detect duplicates: Same menuItemId + variants + addons
Stock is validated at add-to-cart AND again at checkout. Items can go out of stock between these operations.
Duplicate Detection Logic
  • If identical item exists (same menuItemId + variants + addons): increment quantity
  • If different config exists: Check isMultipleVariantOrAddonForMenuItemsSupported flag
  • Flag ON: Add as new item with different cartItemId
  • Flag OFF: Return error with existing item details
➖ Removing Items from Cart
  • Locate target item: First by cartItemId, fallback to menuItemId
  • If quantity > 1: Decrement by 1, recalculate item price
  • If quantity = 1: Remove item from array entirely
  • If no items remain: Delete entire cart document
  • Recalculate cart totals via calculateCartValue()
cartItemId takes precedence over menuItemId for precise item matching. This disambiguates same menu item with different customizations.
📖 Retrieving Cart (getCart)
  • Fetch cart from Firestore by tableId
  • Auto-heal on retrieval: Fix missing arrays, invalid quantities
  • Sanitize price values using price models (prevent NaN)
  • Recalculate totals via calculateCartValue()
  • If cart doesn't exist: Return empty cart structure (not null)
Cart recalculation happens on every getCart call for consistency. This ensures prices are always up-to-date.
🗑️ Clearing Cart (clearCart)
  • Fetch cart document from Firestore
  • Delete entire cart document
  • Returns success message
clearCartInternal is used by checkoutCart. If cart clearing fails after order creation, order is still considered successful (logged as warning).
💰 Price Calculation System
calculateItemPrice Logic
Function: calculateItemPrice(menuItem, selectedVariants, selectedAddons)
  • Get item base price and discount from menuItem
  • Process variants: Sum variant base prices
  • If respectParentDiscount = true: Apply item discount to variant
  • If respectParentDiscount = false: Use variant's own final price
  • Process addons: Same logic as variants for discount inheritance
  • Round all values to 2 decimal places
// Calculation Formula
totalBase = itemBase + variantBase + addonBase
totalFinal = itemFinal + variantFinal + addonFinal
discountAmount = totalBase - totalFinal

// For quantity > 1, multiply by quantity
finalPrice = totalFinal × quantity
respectParentDiscount flag controls whether variants/addons inherit the parent item's discount or use their own pricing.
calculateCartValue Logic
Function: calculateCartValue(cart)
  • Loop through all items in cart
  • Skip cancelled items (status === 'cancelled')
  • Accumulate: basePrice, finalPrice, variant prices, addon prices
  • totalDiscountAmount = basePrice - finalPrice
  • totalDiscount = (totalDiscountAmount / basePrice) × 100
Cancelled items are excluded from totals. Invalid quantities are automatically treated as 1.
Tax Handling
  • Check restaurant setting: includeTaxInFinalPrice
  • If true: Prices already include tax (display as-is)
  • If false: Tax calculated separately at checkout
  • Tax rate stored in restaurant document
Tax calculation is handled at the order level, not in cart price calculations.
✅ Cart Validation
validateCart Function
  • Validates cart structure exists
  • Validates items array is non-empty
  • Checks price consistency for each item
  • If validation fails: triggers recalculation
Stock Validation at Checkout
  • Fetch all menu items from cart
  • Check isInStock flag for each
  • If any out of stock: 412 error with item names
  • Batch fetch for performance
Input Validation (cartInputValidation.js)
Function Required Fields Notes
validateAddItemFields tableId, restaurantId, menuItemId, quantity quantity must be ≥ 1
validateRemoveItemFields tableId, restaurantId, menuItemId cartItemId optional but preferred
validateGetCartFields restaurantId, tableId sessionId optional
validateCheckoutFields restaurantId, tableId sessionId validated separately
validateCheckoutSession restaurantId, tableId, sessionId Session MANDATORY for checkout
Session validation is optional for cart operations but MANDATORY for checkout. Invalid session returns 401 with OTP requirements.
📦 Checkout Flow
🔐 1. Session Validation
  • SessionId is mandatory for checkout
  • If no sessionId → returns 401 with OTP requirements
  • If session invalid/inactive → returns 401 with OTP requirements
Checkout cannot proceed without a valid, active session. This ensures customer tracking and order attribution.
🛒 2. Cart Retrieval & Validation
  • Fetch cart directly from Firestore
  • Validate cart exists → else 412 error
  • Validate cart has items → else 412 error
  • Validate price consistency via validateCart()
  • If prices inconsistent → recalculate via calculateCartValue()
📋 3. Stock Validation
  • Fetch all menu items in cart from Firestore
  • Check isInStock flag for each item
  • If any items out of stock → 412 error with item names
Stock is validated AGAIN at checkout (even if validated when adding to cart). This prevents race conditions where items go out of stock between add-to-cart and checkout.
📝 4. Order Creation via createOrUpdateOrder
  • Checks for existing active order for same table+session
  • If exists: Appends cart as new snapshot to order's carts[] array
  • If not: Creates new order with this cart
  • Generates order number: ORD-00001 format
  • Sets order status to IN_PROGRESS
Items are stored at BOTH order level (items[]) and cart level (carts[].items[]) for different use cases.
🧹 5. Cart Clearing
  • Calls clearCartInternal()
  • Deletes the cart document from Firestore
  • Returns order details to client
If cart clearing fails after order creation, the order is still considered successful. This prevents data loss.

📝 Status Constants Reference
CART_ITEM_STATUS (Before Checkout)
  • PENDING - Initial status for all cart items
Cart items don't change status before checkout. Status changes happen in order.carts[] after checkout.
CART_STATUS (Within Order)
PENDING ACCEPTED PREPARING READY SERVED RETURNED CANCELLED

From Status Valid Transitions To

Transitions are strictly enforced. Invalid transitions throw an error. You cannot skip statuses (e.g., PENDING → READY is invalid).

Flag Name Purpose
