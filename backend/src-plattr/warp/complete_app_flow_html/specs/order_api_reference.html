▶ updateOrderStatus PUBLIC Change order status (COMPLETED, CANCELLED)
Request Parameters
{ "restaurantId": "string", // Required "orderId": "string", // Required "orderStatus": "COMPLETED", // Required - COMPLETED or CANCELLED "sessionId": "string" // Required (unlike other APIs) }
Sample Response (COMPLETED)
{ "status": "success", "message": "Order status updated successfully", "data": { "orderId": "order_b1_001", "orderStatus": "COMPLETED" } }
⚠️ When status is COMPLETED:
  • Bill is revalidated by recalculating all cart prices
  • If prices don't match stored values → 412 FAILED_PRECONDITION error
  • paymentStatus is set to PAID in the order document
  • FCM notification sent to assigned server (if enabled)

▶ updateMenuItemStatus PUBLIC Update individual item status within order (chef-side)
Request Parameters
{ "restaurantId": "rest_basic_001", // Required "orderId": "order_b1_001", // Required "menuItemId": "item_burger_cls", // Required "cartItemId": 1, // Optional - for disambiguation when same item appears multiple times "newStatus": "CANCELLED" // Required - valid CART_ITEM_STATUS }

  • Item is marked cancelled in both order.items[] and corresponding cart.items[]
  • Cart prices are recalculated via calculateCartValue()
  • Total order priceInfo is recalculated across all carts
▶ ORDER_COMPLETED Notification FCM Push notification sent to server when order completed
Trigger Condition
  • updateOrderStatus called with orderStatus: COMPLETED
  • Feature flag sendServerNotifications is ON
  • Table has assignedServerId
  • Server has valid fcmToken
FCM Payload
{ "title": "Order Completed", "body": "Order {orderId} marked complete – please collect payment", "data": { "restaurantId": "restaurant_xyz", "orderId": "order_abc123", "type": "ORDER_COMPLETED" } }
