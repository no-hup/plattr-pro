📋 System Overview

The Plattr authentication system uses OTP-based table access with session management for multi-user collaboration. Authentication involves coordination between 4 entities: Table, Session, Customer, and Server.

🏢 Entities Involved in Auth
🪑 Table
  • Holds status: VACANT, OTP_PENDING, ACTIVE, DISABLED
  • Stores currentOTP: {code, createdAt, expiresAt}
  • Links to session ID when active
  • Tracks occupiedBy: array of customer phones
  • Records primaryCustomer: {phone, name}
🔗 Session
  • Created when first customer validates OTP
  • Stores primaryUserId: phone of first customer
  • Maintains users[]: all customers at table
  • Has status: active, ended, expired
  • Expires after 5 hours or on manual end
👤 Customer
  • Document keyed by phoneNumber
  • Created/updated during OTP validation
  • Tracks currentVisit: {restaurantId, tableId, startTime}
  • Stores historical visits[] array
  • Holds preferences and profile data
👨‍🍳 Server (Waiter)
  • Can generate/regenerate OTP for tables
  • Assigned to tables via assignedServerId
  • Receives notifications on session start
  • Can view active sessions for assigned tables
  • Can manually end sessions (clearing table)
🚩 Feature Flags Affecting Auth
🔑 isOtpMandatoryAtScan
ON: OTP required on every QR scan, even if valid session exists
OFF: Skip OTP if sessionId in localStorage is still valid
Impact: Controls entry friction vs security
👤 isUsernameEnabled
ON: Name field required along with phone during auth
OFF: Only phone number required (name optional)
Impact: Customer profile completeness
👥 isMultiUserSupportEnabled
ON: Multiple users can join same table session
OFF: Only primary customer allowed, others rejected
Impact: Group dining vs single-user mode
📍 Location Validation
Always ON: User location validated against restaurant geofence
Failure: Returns 412 error, blocks access
Impact: Prevents remote ordering abuse

OTP Flow Nuances
  • OTP is stored in table.currentOTP = {code, createdAt, expiresAt}
  • Table status changes to OTP_PENDING when OTP is generated
  • If OTP expires, table status reverts to VACANT (no active session)
  • Server can call regenerateTableOTP to issue new OTP at any time
  • Regenerating OTP invalidates the previous one immediately
  • Max 3 OTP validation attempts before temporary lockout (configurable)
  • OTP validation is case-insensitive (numeric only)

Session Nuances & Edge Cases
  • Session is stored in browser's localStorage for persistence across page refreshes
  • Session validation checks both status = active AND expiresAt > now
  • If session expires mid-order, user must re-authenticate but cart is preserved
  • Primary user leaving doesn't end session - other users can continue
  • Session expiry (5hrs) calculated from creation, not last activity
  • All users in same session share the same cart view
  • If isMultiUserSupportEnabled = OFF, secondary users get 403 error
  • Server/admin can force-end session via endSession API

⚠️ Edge Cases & Error Handling
Authentication Edge Cases
  • Same phone, different device: Both devices can join same session
  • OTP entered on wrong table: Validation fails (tableId mismatch)
  • Internet disconnect during auth: Retry with same OTP if not expired
  • LocalStorage cleared: Must re-authenticate via OTP
  • Page refresh during OTP entry: OTP still valid, can retry
  • Multiple tabs same session: All tabs share same session state
  • Firebase token expired: Must re-authenticate (token refresh not implemented)
Session Edge Cases
  • All users leave table: Session remains active until timeout/manual end
  • Primary user clears localStorage: Can rejoin with OTP, remains primary
  • Session expires with active cart: Cart preserved, re-auth required to checkout
  • Server ends session mid-order: Users get "session ended" error on next action
  • Concurrent OTP validation: First success wins, second gets "already active"
  • Table reassigned mid-session: Old session ends immediately
Recovery Scenarios
Scenario User Experience Recovery Path
Session expired Error on any action Re-scan QR → OTP → New session (cart preserved)
OTP expired OTP validation fails Ask server to regenerate OTP
Wrong OTP 3x Temporary lockout Wait 5 min or ask server to regenerate
Table disabled 403 on scan Contact staff, move to different table
Location mismatch 412 on validation Enable location, retry; or use different network
