📋 System Overview
Key Concepts
  • The Table-Session-Customer system manages restaurant table authentication, session lifecycle, and customer profiles
  • Enables multi-user table access via OTP validation with session-based ordering
  • Tables are identified by QR codes containing restaurantId and tableId
  • Sessions link customers to tables and enable cart/order operations
  • Primary customer validates OTP first and creates the session
  • Secondary customers join the existing session with the same OTP
Only ONE active session per table at a time. New customers join the existing session rather than creating new ones.
🔗 Cross-Entity Flow
Session → Cart/Order Propagation
QR Scan → OTP Validation → Session Created → Cart Operations → Order Created
  • validateOTP returns sessionId
  • addItemToCart requires sessionId
  • checkoutCart creates order linked to sessionId
  • getOrder can filter by sessionId

🔐 Authentication & Validation Flow
📱 QR Scan / validateTableAndLocation
📞 1. Entry Point: Customer Scans Table QR Code
  • QR contains restaurantId and tableId
  • App captures user's GPS location
  • Calls validateTableAndLocation API
✅ 2. Input Validation
  • Required: restaurantId, tableId, userLocation
  • Optional: sessionId (for existing session validation)
🚫 3. Guard Clauses (Early Exits)
  • Table DISABLED → HTTP 403 Forbidden
  • Location check fails → HTTP 412 Precondition Failed
  • Valid sessionId provided → Return success immediately
Location validation is currently stubbed (isWithinRadius always returns true). Future implementation should check if user is within 100m of restaurant.
🔢 4. OTP Generation (VACANT tables only)
  • Generate 6-digit OTP via otpService.createOTPObject()
  • Update table: status → OTP_PENDING
  • Set currentOTP and firstScannedAt
🚩 5. Feature Flag Check
  • If isOtpManadatoryAtScan = true → HTTP 401 with auth requirements
  • If false → Return success with limited access
🚩 Feature Flag Logic
isOtpManadatoryAtScan
Controls if OTP validation is required when scanning QR
ON Every QR scan requires OTP entry (HTTP 401 if not validated)
OFF Limited access granted without OTP; otpRequiredForOrder flag set
isUsernameEnabled
Makes name field mandatory for users
ON Name required for primary customers
OFF Name is optional
isMultiUserSupportEnabled
Allows multiple users per table session
ON Secondary users can join with phone number
OFF Phone number required for ALL users
Requirement Calculation Logic
// Phone number is required when: isPhoneNumberMandatory = (status === VACANT || status === OTP_PENDING) || featureFlags.isEnabled('isMultiUserSupportEnabled'); // Username is required when: isUsernameMandatory = featureFlags.isEnabled('isUsernameEnabled') && potentiallyPrimary;
🔑 OTP System
OTP Configuration
{ VALIDITY_MINUTES: 5, // 5-minute expiry window LENGTH: 6 // 6-digit numeric code }
OTP expires in 5 minutes from generation. After expiry, table reverts to VACANT.
OTP Object Structure
{ "code": "123456", // 6-digit numeric code "createdAt": Timestamp, // OTP generation time "expiresAt": Timestamp // createdAt + 5 minutes }
OTP Service Functions
Function Purpose
generateOTP() Creates random 6-digit numeric string
createOTPObject() Creates OTP with timestamps (code, createdAt, expiresAt)
isOTPValid(otpObject) Checks if OTP hasn't expired by comparing expiresAt with current time
handleOTPGeneration(tableData) Returns existing valid OTP or creates new one
🔓 OTP Validation Flow (validateOTP)
📥 1. Input Requirements
  • Required: restaurantId, tableId, otp
  • Conditional: phoneNumber (required for primary or when multi-user disabled)
  • Conditional: name (required when isUsernameEnabled and primary)
✅ 2. OTP Verification
  • Compare provided OTP with tableData.currentOTP.code
  • If mismatch → HTTP 401 Unauthorized
  • If match → Proceed to session creation
👤 3. Primary vs Secondary Customer Logic
Table Status User Type Actions
VACANT/OTP_PENDING PRIMARY Creates session, sets primaryCustomer
ACTIVE SECONDARY Joins existing session, added to occupiedBy
📝 4. Table & Customer Updates
  • Set status: ACTIVE
  • Set primaryCustomer: { phoneNumber, name } (primary only)
  • Add phoneNumber to occupiedBy[] array
  • Create/update customer profile via customerService.createOrUpdateCustomerProfileDirect()
🎟️ 5. Session & Token Generation
  • Primary: sessionService.createOrGetTableSession()
  • Secondary: sessionService.addUserToTableSession()
  • Generate Firebase custom token using phoneNumber as UID
Phone number is used as the Firebase UID and customer document ID. This creates a direct link between authentication and customer profiles.
⏱️ Session Management
SESSION_STATUS Constants
{ ACTIVE: 'active', // Session in use ENDED: 'ended', // Manually ended (table cleared) EXPIRED: 'expired' // Time expired (4 hours) }
Session expires in 4 hours from creation. After expiry, session status changes to EXPIRED.
Session Document Schema
restaurants/{restaurantId}/sessions/{sessionId}
id string (auto-generated)
tableId string
primaryUserId string (first customer's phone)
users [phoneNumber, ...] (all customers)
status 'active' | 'ended' | 'expired'
createdAt Timestamp
updatedAt Timestamp
expiresAt Timestamp (4 hours from creation)
Session Service Functions
Function Purpose Key Behavior
createOrGetTableSession() Creates new or retrieves existing session If session exists, adds user to it; otherwise creates new with 4-hour expiry
addUserToTableSession() Adds user to existing session Validates session not expired; adds to users[] array
validateTableSession() Validates session for a table Returns session if active & not expired; optionally adds user
endTableSessions() Ends active session for table Sets status: 'ended'
Session Lifecycle
Created → ACTIVE → ENDED or EXPIRED
  • Session created when primary customer validates OTP
  • Secondary customers join the same session
  • ENDED: Manual table clear, bill paid
  • EXPIRED: 4 hours elapsed since creation
🔄 Session Cleanup

The cleanupInactiveSessions function runs to clear stale sessions:

  • Finds tables with lastActivity > 1 hour ago
  • Ends associated sessions
  • Sets table status to VACANT
⚠️ TODO: Should check for cart/order activity in last 2 hours, not just general activity.

Customer Service Functions
Function Type Purpose
createOrUpdateCustomerProfile PUBLIC Creates new or updates existing customer profile
createOrUpdateCustomerProfileDirect INTERNAL Same as above, callable directly (used by validateOTP)
getOrCreateCustomerProfile PUBLIC Gets existing profile (requires auth)
updateCustomerVisit PUBLIC Adds new visit to visits array, sets currentVisit
endCustomerVisit PUBLIC Ends current visit, updates table to vacant
Primary Customer
  • First to validate OTP on VACANT/OTP_PENDING table
  • Creates the table session
  • Stored in table.primaryCustomer
  • Phone number becomes session.primaryUserId
Secondary Customer
  • Validates OTP on already ACTIVE table
  • Joins existing session
  • Added to table.occupiedBy[] array
  • Added to session.users[] array

Entity Relationships

Cross-Entity Links
  • Table → Session: Query sessions by tableId
  • Session → Customers: session.users[] contains phone numbers; customers stored separately
  • Table → Customers: table.occupiedBy[] mirrors session users
  • Session → Cart/Order: Cart and Order operations require sessionId

▶ cleanupInactiveSessions SCHEDULED Clean up stale sessions and reset inactive tables
