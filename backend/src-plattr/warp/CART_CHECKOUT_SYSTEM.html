SPECS: Cart & Checkout System

Core Flow
SPEC-001 Cart is keyed by tableId under restaurants/{rid}/carts/{tableId}
SPEC-002 Adding item requires: restaurantId, tableId, menuItemId, quantity (minimum 1)
SPEC-003 Variants/addons are optional but mandatory variants must be provided if defined on menu item
SPEC-004 Identical item configs (same menuItemId + variants + addons) increase quantity instead of creating new entry
SPEC-005 All cart operations use Firestore transactions to prevent race conditions
SPEC-006 Session validation is optional for add/remove but mandatory for checkout
SPEC-007 Cart is cleared (document deleted) after successful checkout
Data Structure
SPEC-010 Each cart item has unique cartItemId (auto-incremented integer starting from 1)
SPEC-011 selectedVariantsDetails stores full variant info: id, name, isMandatory, respectParentDiscount, selected_variant_id, priceInfo
SPEC-012 selectedAddonsDetails stores full addon info: id, name, priceInfo, respectParentDiscount
SPEC-013 Item priceInfo includes: itemBasePrice, itemFinalPrice, totalVariantBasePrice/FinalPrice, totalAddonBasePrice/FinalPrice, totalBasePrice, finalPrice, discount, discountAmount
SPEC-014 Cart totals stored in cart.priceInfo: basePrice, finalPrice, totalVariantBasePrice, totalAddonBasePrice, totalDiscount, totalDiscountAmount
SPEC-015 Cart item includes full menuItem object snapshot for offline display
Price Calculation
SPEC-020 Base formula: (itemFinalPrice + variantFinalPrice + addonFinalPrice) × quantity
SPEC-021 If respectParentDiscount: true, variant/addon inherits item's discount percentage
SPEC-022 If respectParentDiscount: false, variant/addon uses its own finalPrice directly
SPEC-023 All prices rounded to 2 decimal places using Math.round(price * 100) / 100
SPEC-024 Discount percentage clamped between 0-100, discount amount never negative
SPEC-025 NaN/undefined values sanitized to 0 with console warnings logged
Feature Flags
SPEC-030 isMultipleVariantOrAddonForMenuItemsSupported controls item consolidation behavior (default: true)
SPEC-031 When OFF and different config exists: returns error with existing item details for user confirmation
SPEC-032 fallbackToSameCustomConfigurationForAddItem auto-fills variant/addon selections from existing cart item (default: true)
Validation Rules
SPEC-040 Stock validated at add time: menuItem.isInStock must be true
SPEC-041 Stock re-validated at checkout: batch check all cart item menu IDs
SPEC-042 Mandatory variants validated: all variants with isMandatory: true must have selection
SPEC-043 Session validated at checkout via validateCheckoutSession → must be active and not expired
SPEC-044 Cart price consistency validated before checkout; recalculated if inconsistent
SPEC-045 Quantity must be positive integer ≥1; invalid quantities sanitized to 1
Error Cases
SPEC-050 invalid-argument (400): Missing required fields (tableId, restaurantId, menuItemId, quantity)
SPEC-051 not-found (404): Menu item, variant, addon, or cart not found
SPEC-052 failed-precondition (412): Item out of stock, empty cart, invalid session, mandatory variant missing
SPEC-053 unauthenticated (401): Session required but not provided or invalid
SPEC-054 internal (500): Database access errors, transaction failures
Cross-Entity Effects
SPEC-060 Checkout creates or appends to order in restaurants/{rid}/orders/{orderId}
SPEC-061 Existing IN_PROGRESS order found → cart appended to order.carts[] array
SPEC-062 No existing order → new order created with status IN_PROGRESS, unique orderNumber (ORD-00001 format)
SPEC-063 Cart snapshot stored in order with cartId ({rid}_{tid}_{uuid8}), status PENDING, checkoutTime
SPEC-064 Order counter maintained in restaurants/{rid}/counters/orders for sequential numbering
SPEC-065 Cart document deleted after successful order creation (clearCartInternal)
Edge Cases
SPEC-070 Menu item deleted after cart add → caught at checkout via stock validation (item won't exist)
SPEC-071 Price changed after cart add → NOT re-validated (uses snapshot prices from add time)
SPEC-072 Concurrent cart updates → handled via Firestore transaction with automatic retry
SPEC-073 Session expires during checkout → fails with unauthenticated, prompts re-auth
SPEC-074 Order created but cart clear fails → order succeeds (logged warning), may cause ghost cart
SPEC-075 Remove last item → cart document deleted entirely (not just items array cleared)
SPEC-076 GetCart auto-repairs: recalculates totals, fixes NaN quantities, fills missing arrays

🚩 Feature Flags
🔀 isMultipleVariantOrAddonForMenuItemsSupported

Controls whether multiple configurations of the same menu item can exist in cart

✓ ON DEFAULT

Identical configs merge (increment qty). Different configs allowed as separate entries.

✗ OFF

Only one config per menu item allowed. Returns error if adding different config.

📋 fallbackToSameCustomConfigurationForAddItem

Auto-fills variant/addon selections from existing cart item when adding same menu item

✓ ON DEFAULT

If menu item exists in cart, reuses its variant/addon selections if not provided.

✗ OFF

Always uses provided selections only. No auto-fill from existing cart items.

👤 isUsernameEnabled

Affects checkout session validation error response

✓ ON DEFAULT

Auth error includes isUsernameMandatory: true

✗ OFF

Auth error includes isUsernameMandatory: false

📝 Nuances & Edge Cases
✓ Validation Nuances
  • ✓Mandatory variants checked against menu item's variant definitions, not just provided selections
  • ✓Stock checked twice: at add time (immediate feedback) and checkout (prevents stale cart issues)
  • ⚠Price changes NOT validated at checkout - uses snapshotted prices from add time
  • →Session validation optional for add/remove, mandatory for checkout only
🔄 State Management Nuances
  • ✓getCart auto-repairs: fixes NaN quantities, fills missing arrays, recalculates totals
  • ⚠Cart document deleted when last item removed (not just items array cleared)
  • →cartItemId auto-incremented from max existing ID + 1
  • →Full menuItem snapshot stored for offline display capability
⚡ Concurrency Nuances
  • ✓All cart modifications use Firestore transactions with automatic retry
  • ✓Order creation uses separate transaction from cart clearing
  • ✗If order succeeds but cart clear fails: order exists, cart may remain (logged warning)
  • ⚠Multiple users on same table share single cart document
🔧 Recovery Scenarios
  • →Invalid quantity: sanitized to 1 with console warning
  • →NaN prices: sanitized to 0 using CartItemPriceInfo model
  • →Missing priceInfo: created with defaults using price models
  • ⚠Inconsistent cart totals: recalculated before checkout
💰 Price Calculation Nuances
  • →respectParentDiscount: variant/addon inherits item's discount percentage
  • →Discount clamped 0-100%, discountAmount never negative
  • ✓All prices rounded to 2 decimals: Math.round(price * 100) / 100
  • ⚠Significant price deviations logged but accepted (finalPrice vs calculated)
🔐 Security Nuances
  • ✓Session validated server-side at checkout (not trusting client)
  • →userId defaults to 'system' if no auth context
  • ⚠No rate limiting on cart operations currently
  • →Error responses include context for debugging but not sensitive data

❌ Error Handling
Error Scenario HTTP Code Error Type Message Recovery Path
Missing required fields 400 invalid-argument "tableId, restaurantId, menuItemId, and quantity are required." Fix request payload
Invalid quantity 400 invalid-argument "Quantity must be greater than 0." Provide quantity >= 1
Menu item not found 404 not-found "Menu item not found." Verify menuItemId exists
Cart not found 404 not-found "Cart not found for the table." Add items first
Item out of stock 412 failed-precondition "Menu item is currently out of stock." Choose different item
Mandatory variant missing 400 invalid-argument "Mandatory variant '{name}' must be selected." Select required variant
Session not provided 401 unauthenticated "Authentication required" Complete OTP flow, provide sessionId
Session invalid/expired 412 failed-precondition "Invalid or inactive session" Re-authenticate with OTP
Empty cart checkout 412 failed-precondition "Cannot checkout an empty cart." Add items before checkout
Different config exists (flag OFF) 200 success (with data) "Item exists with different configuration" User confirms or chooses existing config
Stock changed at checkout 412 failed-precondition "Cannot checkout. The following items are out of stock: {names}" Remove out-of-stock items from cart
Database error 500 internal "Error accessing database." / "Error processing checkout" Retry operation
⚠️ All errors include context object with restaurantId, tableId for debugging. Sensitive data is never exposed in error responses.
