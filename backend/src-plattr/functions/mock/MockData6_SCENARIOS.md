# MockData6 — Big Restaurants E2E Scenarios

> **File:** `MockData6BigRestaurants.json` (generated by `buildMockData6.js`)
> **Built for:** MVP launch testing — two large, realistic restaurants modeled on
> the real **Toit Brewpub** and **Karavalli** (Bengaluru) menus, with edge cases
> for every backend state machine and feature flag **baked in**.

---

## 0. How to (re)generate & import

```bash
cd backend/src-plattr/functions

# (Re)generate the JSON — re-runnable, timestamps relative to "now":
node mock/buildMockData6.js
#   --out=<path>   write somewhere else

# Import into the emulator using the EXISTING loader (--file flag):
FIRESTORE_EMULATOR_HOST=127.0.0.1:8080 \
  node mock/importMockData5.js --file=mock/MockData6BigRestaurants.json --clean --refresh-timestamps
```

`--clean` wipes the emulator first; `--refresh-timestamps` rewrites every
`{_seconds,_nanoseconds}` to ~now (and `expiresAt` to the future) so orders look
"live" and OTPs/sessions are valid.

> ⚠️ The loader only imports the `restaurants` and `customers` keys. The
> `_meta` and `_system` keys in the JSON are **informational** and are NOT
> auto-loaded — see [§9 Feature Flags](#9-feature-flag-testing) for the
> one-liner to apply the `_system/featureFlagOverrides` doc.

## 7. Price-calculation reference (verified exact values in the seed)

Discounts apply **per component**. `respectParentDiscount` controls whether a
variant/addon inherits the item's discount %.

**Basmati Blonde (20% off) × 2, Mug pour (+150, respectParentDiscount=false):**
```
Beer:  220 → 176 (20% off)
Mug:   +150 (NOT discounted — variant respectParentDiscount=false)
Per unit: base 370, final 326   →   ×2 = base 740, final 652   ✅ (in ord_toit_active)
```

**Margherita (10% off) + Extra Cheese (+60, respectParentDiscount=false):**
```
Pizza: 475 → 427.5 (10% off)
Cheese: +60 (NOT discounted)
base 535, final 487.5   ✅
```

**Order totals + Charges V1** (charges are a separate line list on `finalPrice`,
NOT folded into it; grand total = `finalPrice + chargesTotal`):

`ord_toit_active`: base 2770, final 2634.5, +SERVICE_CHARGE 7.5% = **+197.59** → grand **2832.09**

`ord_kara_active`: base 7425, final 7250, charges = SERVICE 10% (+725) +
PACKAGING 2% (+145) + **LOYALTY −5% (−362.5)** = **chargesTotal 507.5** → grand
**7757.5**  *(exercises a negative-percentage charge)*

## 8. Offers — what applies, what doesn't, and why

Offers V2 auto-apply at checkout; the engine picks the **single best** (highest
discount, then lowest `priority`). Scopes: `ORDER`/`CATEGORY`/`ITEM`. Types:
`PERCENTAGE`/`FLAT`/`BOGO`/`FREE_ITEM`.

### Toit — valid
| Offer | Type / Scope | Condition | Test |
|---|---|---|---|
| `off_toit_food10` | PERCENTAGE / CATEGORY (appetisers+large) | — | 10% off, max ₹300 |
| `off_toit_bar_flat100` | FLAT / CATEGORY (brews) | `minOrderValue 500` | <₹500 bar → none; ≥₹500 → ₹100 off |
| `off_toit_bogo_blonde` | BOGO / ITEM (Basmati Blonde) | — | Buy 1 get 1 free |
| `off_toit_free_dessert` | FREE_ITEM / ITEM (tiramisu/layer cake) | `requiredItems: char steak ×1` | Free dessert only if steak in cart |
| `off_toit_order15_cap` | PERCENTAGE / ORDER | `minOrderValue 1500` | 15% off, **capped ₹250** |
| `off_toit_firsttime` | PERCENTAGE / ORDER | `userHistory.minOrderCount 0` | First-order 20% (max ₹200) — see note ▼ |
| `off_toit_pizza_excl` | PERCENTAGE / CATEGORY (pizzas) | `exclusionIds: shrimp pizza` | Shrimp pizza excluded |

### Toit — NEGATIVE (must NOT apply)
| Offer | Why it must be rejected |
|---|---|
| `off_toit_expired` | `endDate` in the past |
| `off_toit_future` | `startDate` in the future |
| `off_toit_inactive` | `isActive:false` (also filtered by the query) |

### Karavalli — valid
| Offer | Type / Scope | Condition |
|---|---|---|
| `off_kara_seafood10` | PERCENTAGE / CATEGORY (grill) | max ₹500 |
| `off_kara_dessert_flat` | FLAT / CATEGORY (desserts) | `minOrderValue 3000` |
| `off_kara_loyalty` | PERCENTAGE / ORDER | `userHistory.minOrderCount 2` (repeat guest) |
| `off_kara_bogo_appam` | BOGO / ITEM (appam) | — |
| `off_kara_combo_required` | FREE_ITEM / ITEM (payasam) | `requiredItems: sea crab ×1` |

### Karavalli — NEGATIVE
| Offer | Why |
|---|---|
| `off_kara_badscope` | `scope:"CART"` is invalid → engine rejects |
| `off_kara_empty_target` | CATEGORY scope with empty `targetIds` → rejected |

> **First-time-user note:** the engine does **NOT** honour a `conditions.isFirstTimeUser`
> flag (it's dead). "First-time" is modeled correctly via
> `userHistory.minOrderCount`, which the engine evaluates as orders carrying the
> current `sessionId`. A session with **0** prior orders = first-time. To make the
> loyalty offer (`minOrderCount:2`) fire, the session needs ≥2 orders with that
> `sessionId`.

## 9. Feature flag testing

The 4 flags (`isOtpManadatoryAtScan`, `isUsernameEnabled`,
`isMultiUserSupportEnabled`, `sendServerNotifications`) are **global**, overridable
via the `_system/featureFlagOverrides` Firestore doc (emulator). The seed ships
this block at **production defaults** (so nothing surprises your suite).

**To exercise the seeded multi-user table (`tbl_toit_2`)**, flip the flag:

```bash
FIRESTORE_EMULATOR_HOST=127.0.0.1:8080 node -e '
const a=require("firebase-admin"); a.initializeApp({projectId:"rms-app-dd875"});
a.firestore().doc("_system/featureFlagOverrides").set({
  isOtpManadatoryAtScan:true, isUsernameEnabled:true,
  isMultiUserSupportEnabled:true, sendServerNotifications:false
}).then(()=>{console.log("multi-user ON");process.exit(0)});'
```

The multi-user *data* (2 occupants on table 2, `users:[…11,…10]` on
`ses_toit_multi`) is always present; the flag only gates whether a 2nd user may
**join** at runtime.

## 10. Edge-case checklist

- [ ] **Out-of-stock items** blocked from cart: `ti_beer_prawns`, `ti_toit_red`,
      `ki_surmai_tawa`. **Out-of-stock addon**: Prawns on Quinoa Salad.
- [ ] **Inactive kitchen** (`kit_toit_dessert`) / **inactive server**
      (`imran@toit.in`, login rejected).
- [ ] **Expired OTP** on `tbl_toit_4` → re-scan should mint a fresh OTP.
- [ ] **Disabled / reserved** tables not bookable via normal scan.
- [ ] **Cancelled item** inside an active order (`okra` in `ord_toit_active`) is
      dropped from `order.items[]` but kept in the cart snapshot.
- [ ] **Returned item** (`ki_kadala_gassi` in `ord_kara_active`).
- [ ] **Partially-paid** order (`ord_kara_active`).
- [ ] **Negative billing charge** (Karavalli LOYALTY −5%).
- [ ] **Carousel categories** (`tc_pizzas`, `tc_bestsellers`, `kc_popular`,
      `viewType:"carousel"`) and **cross-listed** items (6 Toit favourites appear
      in `ts_bestsellers` via `subcategoryIds`).
- [ ] **Inactive menu** (`menu_toit_monsoon`, `isActive:false`) → active-menu
      selection must pick `menu_toit_main`.
- [ ] **Optional vs mandatory variants** (Karavalli rice Portion optional;
      beer Pour mandatory).
- [ ] **respectParentDiscount true vs false** (see §6/§7).
- [ ] **First-time vs returning** offers via `userHistory` (§8).

## 11. What this FIXES vs MockData5

`buildMockData6.js` corrects latent schema bugs that the old mock carried
(verified against the live backend + Flutter models):

| MockData5 issue | MockData6 |
|---|---|
| Cart items used dead field `kitchenStatus` | Uses **`status`** (FULFILLMENT_STATUS) — the field the backend actually reads |
| Server `role:"waiter"` (fails role gate) | Canonical **UPPERCASE** `SERVER/KITCHEN/MANAGER/ADMIN` |
| Variants missing top-level `name` (Dart parse fail) | Every variant has top-level **`name`** + `meta.name` |
| Menu items missing `nutritionalInfo` (required in core Dart model) | Every item has **`nutritionalInfo`** |
| Offers used dead `conditions.isFirstTimeUser` | Uses engine-honoured **`userHistory.minOrderCount`** |
| Carts referenced a `session_active_1` that didn't exist (orphaned) | All `sessionId` references resolve to real seeded sessions |
| Cart items lacked top-level `categoryId`/`subcategoryIds` | Present → CATEGORY/ITEM offers actually match at checkout |
| Live cart vs order-cart-snapshot shapes conflated | Live carts (id==tableId) carry NO `status`/`cartId`; order `carts[]` snapshots carry `cartId`/`status`/`statusHistory`/`checkoutTime`/`estimatedPrepTime`/`assignedTo` |
